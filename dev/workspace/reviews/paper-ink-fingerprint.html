Paper/Ink Fingerprint

Every HTML artifact in this repository built on the prompt-builder's design system, and the one string that finds all of them and nothing else.

The signal

15/15 · 0 collisions
Search for this --surface-sunk

A CSS custom property from the Paper/Ink palette. It appears 5–10 times in every family member, survives partial copies, and — unlike every rival below — is not a word anyone would write in prose.

# current branch, including the dev/branches/ archives
grep -rl --exclude-dir=.git -- '--surface-sunk' .

# every commit on every branch
git grep -l -- '--surface-sunk' $(git rev-list --all) -- '*.html' \
  | awk -F: '{print $2}' | sort -u

Note the -- before the pattern. Without it grep reads --surface-sunk as a bundle of options and silently returns nothing.

Rivals tested

Nine candidates were run against all 88 unique HTML blobs in history. Six scored a perfect 15/15 with zero false positives, so recall did not decide it — collision risk did.

--surface-sunk Pick

15/15. No natural-language failure mode; "sunk" is an idiosyncratic name for a recessed surface, which is exactly what makes it safe.

--ink-faint Backup

15/15, equally safe. Denser than the pick — 10–35 hits per file — so it is the better choice when confirming a suspected match rather than sweeping.

Source Serif 4 Backup

15/15. Reliable inside HTML, but any document that merely describes the system will name the font too.

standfirst Rejected

15/15 here, but it is a real journalism term. It will match prose about the design as readily as the design itself.

Bitter Rejected

15/15 here, and a common English adjective. Useless the moment the search widens past *.html.

class="shell" Rejected

15/15 here purely by luck. shell is among the most generic class names in circulation and will not transfer to another repository.

--paper  /  #ECF0EF Wider net

16 hits — the 15, plus fsa-probe.html, which carries the palette's hex values under abbreviated token names. Use these two to trace the palette lineage rather than the full design system.

What makes a document in-family

measured, all 15

The signal is a shortcut to this. When judging a borderline file by eye, these are the marks to look for — but only the first tier is actually reliable. Each convention below was counted across all fifteen family members, and the tiers are the counts, not an ideal.

Always present 15 of 15

  • ✓The token vocabulary. A paper/surface/ink naming scheme rather than a bg/panel/text one, with -soft companions paired to --accent and --warn. This is what the signal detects.
  • ✓The type triple. One Google Fonts link carrying Bitter, Source Serif 4 and JetBrains Mono, each declared with a real system fallback so the page still reads when opened offline from disk.
  • ✓The .shell wrapper, holding a mono uppercase .eyebrow strip and a .standfirst capped near 62–70 characters.
  • ✓A .sec-head section header — a heading, a rule beneath it, and a mono count pushed right. Between four and eight per document, in every one.

Near-universal 14 of 15

  • ·A .masthead header. Process nesting — demo is the exception: it keeps the eyebrow and standfirst but hangs them off a bare <header>.
  • ·A third theme block. Most carry all three — a bare :root light palette, a prefers-color-scheme block guarded by :root:not([data-theme="light"]), and a :root[data-theme="dark"] block so an explicit toggle beats the OS in both directions. The same demo file stops at two, because it has no toggle to honour.

Tool-only 5 of 15

  • ·A pre-paint theme restore. An inline <script> in the head reading a remembered theme from localStorage and stamping data-theme before first paint, wrapped in try/catch. Every occurrence is a Prompt Builder version — the review documents never persist a theme.

Late addition 2 of 15

  • ·A data-URI SVG favicon. A rounded square carrying one serif initial, tinted with the page's own accent — teal in the builder, amber in the demo. It appears only in the two most recent files, so treat it as where the system is heading rather than a test of membership.
A second signal, if you want the halves

The family has two lineages, and one string separates them without error. masthead-meta appears exactly three times in all six drafthorse review blobs and never once in the nine prompt-builder blobs — a clean 6/9 split with no overlap. Search it when you want the review documents specifically.

Narrower still: --del-bg picks out only the pages that actually render a diff — The De-hold Patch and Spec-check Catch-up. Retiring De-hold is prose review rather than a diff view, so it carries the masthead-meta mark but none of the diff colours.

The one edge case

fsa-probe.html

Exactly one file in the repository sits on the boundary, and it is worth knowing about because it will surface if you search by colour instead of by token.

Storage Probe

Palette cousin · 274 L · branch artifacts
What it shares
Every hex value, light and dark, matched exactly against the reference implementation.
What it does not
Token names are abbreviated — --sunk, --soft, --faint, and --ok/--no where the system says --accent/--stop. No web fonts are loaded. The wrapper is .wrap, the intro is .lede, and there is no masthead or third theme block.
Verdict
Not a family member. A throwaway diagnostic — it checks whether Chrome grants the File System Access API from file:// — that borrowed the colours and nothing else.

This is the practical difference between the two kinds of signal. --surface-sunk asks does this follow the system, and excludes the probe. #ECF0EF asks where did this palette travel, and includes it. Pick the question you actually mean.

Where it started

2026-08-19

The design system did not begin in the prompt-builder. The three oldest family members all date to 19 August and all sit on drafthorse review branches — Retiring De-hold, The De-hold Patch and Spec-check Catch-up, each a compact 487–762 line review document. The prompt-builder's first version in this style lands two days later on 21 August at 1,501 lines and grows to 3,685 by 23 August.

The session transcript that produced the builder says so outright. Two lines from dev/workspace/history/ea347861_prompt-builder-design-and-build.txt:

Confirm the palette: issue-45's teal-on-paper with Bitter / Source Serif 4 / JetBrains Mono, versus the tuner's Anthropic clay-on-ivory.

Palette, fonts, chips, and card treatment lifted from issue-45.

So the system was worked out on short review pages and then scaled up into a tool — which is why the reference implementation carries component vocabulary (chips, rows, stages, meters) the review documents never needed, and why the builder is the last place to look for the system's origin despite being its fullest expression.

Nothing specifies this

The system exists only as copied HTML. No skill, rule, template or README in the repository defines these tokens — nothing in extensions/rules, extensions/skills, docs/, or any CLAUDE.md. The only non-HTML mentions anywhere in history are two session transcripts in dev/workspace/history/, including the one quoted above. Both are records of a conversation, not a spec, and neither gives the system a name.

That is the practical reason a search signal is worth having: until the system is written down, --surface-sunk is the only reliable way to find every page that follows it.
