01Integrateedit mode

Edit mode, resetting on entry

A toggle turns every pick field editable in place. Chips stop selecting and start editing — dashed and amber, so the mode is never in doubt. Each carries a delete, each opens a key-and-value pair, and a new option can be added at the end.

Entering clears what you filled in, which is what removes every orphaned-selection problem. One plain warning before it happens.

Pick something, then turn editing on and watch the selection go. Rename a key, change its value, add an option, delete one.

02Integratebuilders panel

Order and visibility in one panel

Drag to reorder, or focus a row and press Alt with the arrow keys. The toggle takes a builder out of the dashboard and out of the prompt without losing its place in the order, so switching it back on returns it where it was.

Stored as the full ordered list plus a separate list of what is off. Both travel with the loadout.

03Integrateloadouts

Import replaces everything

This is the correction. Import currently patches key by key, so a smaller file leaves the previous options sitting underneath it. A loadout is a whole tool — options, keys, values, order, visibility — and loading one has to leave nothing of the last behind.

A loadout names itself in the file, and the name shows in the masthead so you can tell which one is loaded at a glance.

live · two loadouts over the same three fields

Swap between them. The counter reports what was replaced and what disappeared entirely — that second number is the one merge would leave behind.

One guard: a file with a handful of keys and no order is a fragment, not a loadout. The page should say so and offer to merge it rather than wiping fourteen builders.

04Your callsave warning

Warn once, or warn every time

Save rewrites the option block inside the page's own file. You asked whether a backup warning is the way — here are both, running. Press Save twice in each.

My reading: a dialog you see on every save becomes one you dismiss without reading, which leaves you less protected than no dialog. Warn once, name the file, and put Export in the dialog so a backup is one click from the moment of risk. But it is your file and your risk appetite.

05Integratecopy or write

Copy and write, side by side

The correction in your two-paths plan: a typed path cannot be written to. Writing needs a folder you pick once through a dialog, which the page then remembers. So the two settings are different kinds of thing, and only one of them is a text field.

  • Project path — text. Only ever substituted into {{path}} in recipes and utilities.
  • Prompt folder — a picked folder, remembered. Cannot be typed, because a string carries no permission.

08Your callvocabulary

Builder or section

You are right that each one builds a part of the prompt, and that the tab is already called Build. The single objection is overloading — the page is the Prompt Builder, so "builder" would name both the whole and the parts.

In practice context carries it. Nobody misreads "the Skills builder". Here is the same copy both ways.

09Deferprompt library

Prompt library

To answer the question directly — it replaces nothing. It would list the same JSON files Export already writes, so you pick from names instead of a file dialog. Import and export stay exactly as they are.

It is the weakest of the five and it duplicates something that already works, so it waits until you miss it.

10Deferrepo browser

Repo browser — yes, it is a working-directory memory

Bind the project root the same way the prompt folder gets bound. The page then remembers it, and the Context "files to read first" and References fields stop being boxes you type paths into and become lists you pick from. No typos, no guessing at a path from memory.

Cost is a permission grant over the whole repository and a file-tree widget, which is the largest single piece of UI on the list. The folder-handle machinery lands with proposal 05 regardless, so adding this later is small. Waiting.
