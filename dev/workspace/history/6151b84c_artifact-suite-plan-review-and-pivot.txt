## What is the "artifact tool"?

It's **my Artifact tool** — the claude.ai publishing tool I have in this session. It takes an HTML file, wraps it in a `<!doctype html><head></head><body>` skeleton, and hosts it as a private page on claude.ai with a shareable link, under a strict CSP (no external hosts except Google Fonts).

You read it right, and the dependency is bigger than it looks. Compatibility with it is the **sole** reason the plan has:

- the bare-fragment rule (no doctype/html/head/body) — D-18
- quirks mode from disk, and four avoidance rules written to survive it
- `\2212` / `\00B7` CSS escapes, because `<meta charset>` is inert under the wrapper
- check V6a, which serves every fixture twice and compares screenshots
- unresolved question Q4

All of that buys one feature: a shareable cloud link. For throwaway review and interview pages that never leave your machine, it buys nothing. Drop it and the shell becomes an ordinary HTML document — standards mode everywhere, Q4 and V6a both disappear. The page I built has a doctype and works fine.

## How demos work

Split a demo into two halves. Only one is bespoke.

```js
SUITE.demo("d-origin", function (d) {

        document.documentElement.dataset.origin = v;
        d.out("primary chip is now " + d.$(".ref-chip.ref-disk") ? "Open file" : "GitHub");

    });
});
```

Four helpers cover nearly everything a demo does: `d.out(text)` writes the readout, `d.note(text)` the transient line, `d.report(state)` sets `dataset.state` so the return prompt picks it up, `d.on(evt, sel, fn)` delegates within the demo only.
