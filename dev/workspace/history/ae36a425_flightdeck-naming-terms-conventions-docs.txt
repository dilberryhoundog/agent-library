Read the workspace: Stage-1 decisions, the tech plan's file layout (`extensions/skills/artifact-suite/…`, built pages → `dev/workspace/artifacts/<id>.html`), PIVOT's open decisions. Takes below.

**1. Name — FlightDeck works, with one split**
- Fits the library's naming register (DraftHorse, git-box, magic-reply). Distinct from "artifact", which is overloaded 3 ways here (Artifact tool, `dev/workspace/artifacts/`, the skill name). That alone justifies a coined name.
- Real issue: you have two kinds of thing, not one. (a) **durable instruments** — prompt-builder: opened daily, versioned, has state (localStorage/FSA), lives in `extensions/`. (b) **task pages** — review/interview/demo: generated once, disposable, live in the workspace, carry a return prompt. Same shell, very different lifecycle.
- Suggest: **FlightDeck** = the family (shell + conventions + skill). Two profiles under it: **deck** (durable) and **page** (task). Resist theming the sub-names (sortie/instrument) — durable-documents rule: any coined term needs a home in the doc; two coined terms is enough.
- Caution: "deck" collides with slide decks in chat. Minor, define it once.

**2. Location — kind decides, not one bucket**
- Claude placing reviews in `reviews/` and plans in `plans/` is right: dw dirs already carry meaning, and archive/commit/history all work on them for free. A catch-all `artifacts/` duplicates that meaning and hides the page's purpose.
- Proposed landing rule: review page → `reviews/`; interview/options/decision page → `plans/` (or `context/` once answered = decision record); demo/dashboard/anything with no natural home → `flightdecks/` (rename of the experimental `artifacts/` dir). The plan already has a "landing rule" slot; this fills it.
- Durable decks: `extensions/flightdecks/<name>/<name>.html` (rename `extensions/artifacts`), symlinked into a plugin like every other asset. Skill assets (shell, templates, blocks) stay inside the skill dir — they're build material, not decks.
- Repo docs: mirror DraftHorse — `docs/flightdeck/` for framework conventions/profiles/delivery, skill at `extensions/skills/flightdeck/`, optional rule in `extensions/rules/`.

**3. dw integration**
- dev-workspace is its own repo; the scaffold change (add `flightdecks/` + `.keep`) belongs there, and the tree config picks it up automatically. Cheap.
- Worth a named tree (`dev-workspace tree`) listing decks/pages across workspace + `dev/branches/` archives — that's your "high-level insight" surface for pages.
- Archives are the killer feature: task pages snapshot with their context. Argues strongly for pages living *inside* `dev/workspace/`, never in scratch/tmp.

**4. Delivery — settle the open decision as "keep Artifact compat"**
- Three surfaces: disk (`file://`, disk-primary links per D-18), published Artifact (stable URL, shareable), browser-MCP for verify. Compat cost is small (verify writes the wrapped copy) and it's the only way a durable deck becomes a true daily driver across machines/projects.
- Convention: decks publish once with a stable URL recorded in the deck's README (redeploy same path); pages stay on disk, publish only on request. Cross-project deck access otherwise goes via `${CLAUDE_PLUGIN_ROOT}` after plugin install.

**5. Profiles as the documented axis**
- deck: persistent state, versioned with a plugin, no return prompt, own README.
- page/respond: respond surface + return prompt, kind→dir landing, disposable.
- page/read-only: demo, dashboard, figure — no state.
- Profile is what the skill dispatches on; templates hang under it.

# B) CONVENTIONS (grouped by topic)

## B1. File form

- **Bare fragment** — the shell ships no `&lt;!doctype&gt;`, `&lt;html&gt;`, `&lt;head&gt;` or `&lt;body&gt;`; Chrome supplies them from `file://`, the Artifact tool supplies its own. P `### Form`; D-18. **Open** (V §8: build against *dropping* the dependency and shipping a real doctype).
- **Quirks-mode avoidance (four rules)** — lowercase class/id names only; explicit `font-size`/`line-height` on `td`/`th`; no percentage heights; no image in a table. P `### Form`. Settled *conditional on* B1's open decision.
- **Non-ASCII CSS `content` written as escapes** — `\2212` (diff minus), `\00B7` (eyebrow separator), because `&lt;meta charset&gt;` is inert under the wrapper. P `### Form`. Same condition.
- **Version stamp on line 1**, read by text and not by line number. P `### Form`; V §3. Settled (read-by-text amendment binding).
- **Self-contained single file** — no external asset beyond the Google Fonts link and the data-URI favicon. P; `R/paper-ink-fingerprint.html`.
- **Data-URI SVG favicon** — rounded square in the page's own accent; the shell's is a fixed literal (teal `#0D6B64` with three `#F4F6F6` paper bars). P `### Document order`; described as a "late addition" family mark in `R/paper-ink-fingerprint.html`.

## B2. Location and landing

- **Built pages land in `dev/workspace/artifacts/&lt;id&gt;.html`**, where `&lt;id&gt;` is `#page-meta.id`. P File layout; D-19.
- **`dev/workspace/reviews/`** keeps its documented meaning — reviews of completed work — and holds the Stage 1 corpus. P File layout.
- **`dev/workspace/filebox/`** is a temporary location, purged regularly. `filebox/README.txt`.
- **Both directories archive to `dev/branches/&lt;branch&gt;/` identically**, so the mirror route works for either (PR-8). P.
- **Id collision check before `cp`** — `ls dev/workspace/artifacts dev/branches/*/artifacts`; on `file://` every local page shares one origin, so a duplicate id silently merges two pages' answers (AR-8, ST-3). P.
- **Skill lives at `extensions/skills/artifact-suite/`**; symlinked into `plugins/chat-tools/skills/`. P; D-19. **Withdrawn** by V §1 (release packaging out of scope).

## B3. Naming

- Page file name = `&lt;id&gt;.html`; `&lt;id&gt;` = `#page-meta.id` = kebab slug of the subject, permanent once published.
- Card id = kebab subject slug; a stable external identifier (`ds-1`, `issue-45`) is valid; an ordinal is not. Enforced by S4 (`^[a-z]?\d+$` rejected) and a runtime warning.
- Section id = lowercase slug of its `h2`; permanent.
- Radio group `name` = `v-&lt;cardId&gt;`.
- `&lt;title&gt;` = `#page-meta.title` = `&lt;h1&gt;` — disagreement warns via `checkTitles()` and fails S7.
- ToC / `.rail` naming: table of contents is `.toc`; `.rail` reserved (D-5). A block needing an element named `rail` scopes it; the figure block's SVG class is renamed `.track`.
- `layout`, `card`, `section`, `show` are reserved keywords, never marker names.
- Reserved for demos/blocks: every shell id, `data-theme`, every token, every shell class (`.status`, `.card`, `.chip`, `.respond`, `.toc`, `.filters`, `.floater`) even where the shell's rule is scoped elsewhere.

## B4. Theme and tokens

- **Three theme blocks, always** — light on bare `:root`; dark under `@media (prefers-color-scheme: dark)` guarded by `:root:not([data-theme="light"])`; dark again under `:root[data-theme="dark"]`. Copied byte-for-byte from PB lines 21-74 with aligned-colon formatting. P `### Tokens`; DS-1.
- **14 original tokens + exactly 7 added** (`--add-bg`, `--add-ink`, `--del-bg`, `--del-ink`, `--keep-ink`, `--add-mark`, `--del-mark`). No other token is ever added. P `### Tokens`; DS-8, DS-14, DS-16.
- **Radius is hardcoded, not tokenised** — 2px on controls, 3px on cards, stated as one comment: "No token — indirection over a constant."
- **Two prose measures, set once** — 68ch on `.card p/ul/ol` and `.sec-intro`; 62ch on `.standfirst`, `.gloss`, `blockquote`.
- **No template or block ever names a font family, a raw colour, or restates a shell selector.** DS-4, DS-16.
- **Three-way theme control** — System / Light / Dark; System removes both the `data-theme` attribute and the stored key. D-4.
- **`:has()` policy** — allowed (Chrome ≥105 target); a `:has()` rule may only add a state the native control already expresses, never shares a selector list with a non-`:has()` selector, and the one load-bearing use (`.verdicts label:has(input:checked)`) carries an `@supports` floor.

## B5. Marker regions and how a page is written

- **Seven marker regions, each exactly once.** Original set: `@doc-title`, `@page-meta`, `@masthead`, `@template-style`, `@content`, `@sidebar`, `@template-script`. **Amended set (V §7, binding):** `@doc-title`, `@page-meta`, `@masthead`, `@content`, `@sidebar`, `@demo-style`, `@demo-script` — count stays seven so S2 stands verbatim.
- **Two fill semantics** — *placeholder regions* (`@doc-title`, `@page-meta`, `@masthead`) ship one element which is replaced, never appended to; *empty regions* fill by rewriting the closing marker into content-plus-the-same-closing-marker.
- **One writable attribute outside the markers**: the `class` on the single `.shell` element (`rail` or `board`, nothing else).
- **Every other byte outside a marker is fixed chrome.**
- **Section end markers** — each `&lt;section&gt;` carries `&lt;!-- @end-&lt;sectionId&gt; --&gt;` before its closing tag, because `&lt;/section&gt;` is not a unique Edit anchor. V §6, binding.
- **A page is created by `cp`, never by writing chrome.** P `### Form`; AR-1, AR-15.
- **Never read the shell; never read a page copy in full** — bounded `Read` with `offset`/`limit` unlocks Edit for the whole file; ranges are bounded with `grep -n` and one should "err wide". P invariant as amended by V §4, binding.
- **`splice.py`** — the original seven-form splice tool. **Deleted** by V §6; replaced form-by-form with `Edit`, bounded `Read`, and `grep -n 'article class="card'`.
- **The shell carries everything reusable** — every CSS class a template uses pre-exists in the shell; all base JS lives in the shell; nothing is spliced, lifted or pasted between files *at build time*. V §5, binding. (Authoring the shell itself still transcribes from `prompt-builder.html`, `section-ledger.html` and `corpus-sweep-design.html`.)

## B6. Storage

- **Key shape**: `artifact-suite.page.&lt;id&gt;` for the page document; `artifact-suite.theme` (shared across all artifacts) for the theme. Nothing else is ever written. Enforced by V8. D-6, AR-8.
- **One JSON document per page**, read once at boot, written once per 200ms-debounced change; `schema: 1`, `pageId`, `rev`, `savedAt`, `cards{}`, `sections{}`, `orphans{}`.
- **Per-card record**: `verdict`, `comment` (raw newlines kept), `fingerprint`, `answeredAt`, `touched`, `rev`. Orphans add `title`.
- **Every `localStorage` access wrapped in try/catch** with an in-memory `MEM` fallback; when `CAN_LS` is false the footer renders "This browser is not saving answers — copy the prompt before you close the page."
- **Demos store nothing** — the page has one document under one key; demo state lives in memory or `dataset`.
- **Keep every answer** — a removed card's answer is held, not dropped; a changed card is flagged, not cleared. D-7 (explicitly "flagged, not lost", correcting prompt-builder's discard-on-change policy).

## B7. Return prompt format

Exact shape (P `### Return prompt`), settled:

```
## &lt;prompt.heading or title&gt;

Source: &lt;root/self&gt; · branch &lt;b&gt; · issue|pr &lt;url&gt; · rev &lt;n&gt; · built &lt;YYYY-MM-DD&gt;
Untouched: N left at their recommended default, M unanswered.
Held: N answers for cards no longer on this page (id, id).

### Decisions

**&lt;cardId&gt; · &lt;h3 text&gt;**
- Verdict: &lt;value&gt;
- Note:
  &lt;two-space-indented lines, blank lines bare&gt;
- &lt;data-report&gt;: &lt;state&gt;

### Next

- &lt;each META.next entry&gt;

Re-open: file://…
```

Rules: heading is `"## " + (prompt.heading || title)` with no leading `##` in the data; `Source:` joins present values with ` · `, empties dropped; `Untouched:` is two bare counts naming no card, each clause dropped at zero; `Held:` lists ids only and appears only when orphans exist; `### Decisions` lists touched cards in document order, then touched `data-loose` sections as `**&lt;sectionId&gt; · &lt;h2 text&gt;**`; a single-line note is inline, a multi-line note is indented two spaces with blank lines bare; a radio token is never upper-cased; filtering never affects composition; the whole prompt is `""` when nothing is touched and no orphan is held, and Copy then flashes "Nothing answered yet — nothing to copy."

## B8. Link and URL derivation

- **No template ever writes a literal href** — every URL is derived at load from `META.provenance`. Enforced by S6. PR-2, PR-5, AR-12.
- URL templates: Disk `"file://" + encPath(root + "/" + diskPath)` (no line fragment); Editor `editor + "://file" + encPath(...) + ":" + firstLine`; GitHub blob `repo + "/blob/" + ref + "/" + encPath(path) + lineAnchor`; Issue/PR/Branch/Commit `repo + "/issues/"|"/pull/"|"/tree/"|"/commit/"`.
- `encPath(p)` percent-encodes each segment; line suffixes append *after* encoding.
- **GitHub pins to the commit the agent read**; `ref` becomes a branch name only when the block names one; `data-commit` overrides. D-12, PR-11 ("never named `base`").
- **Every outbound link carries `target="_blank" rel="noopener"`**; in-page `#` anchors never do. D-13; V13.
- **Exactly one `.ref-chip` is solid per reference** (PR-10), chosen by CSS off `data-origin`.
- **Origin gating hides `.ref-disk` and `.ref-editor` on the web** (the `.ref-editor` half is V §9's fix) and both plus GitHub-primary on `ref--nodisk`.
- **Absolute checkout path is accepted in the page** (D-11). **Open** — V §8 second decision; build against keeping it.
- **`data-find` (scroll-to-text) is reserved and not implemented.** PR-13.
- **A diff block is always preceded by a `details.ref` naming its file.**
- **Every `.path` element must sit inside a `.ref` or `.ref-link`** — `auditPaths()` flags strays with `path--unlinked` and a `console.warn`; S5 fails the build.

## B9. Script dialect and placement

- **Two scripts only**: the pre-paint script above `&lt;style&gt;`, and one engine IIFE `(function () { "use strict"; … })();` at the foot. Templates contribute no JavaScript.
- **prompt-builder's dialect**: `var`, function declarations, string concatenation. **No** arrow functions, template literals, optional chaining or `class`.
- **Callers above callees**, ordered by invocation, under twelve fixed banners: Boot, Meta and capabilities, Storage, Fingerprints, Respond surfaces, Restore, Recording, Provenance, Navigation and filters, Return prompt, Clipboard and status, Theme. (`extensions/rules/STYLE.md`.)
- **Comments state constraints only** (`extensions/rules/code-comments.md`); exactly three earn one: the shared `file://` origin, `localStorage` throwing, and the `&lt;/` rule.
- **The `&lt;\/` rule** — a literal `&lt;/` inside any JSON or JS string ends the script block, so it is written `&lt;\/`. ST-11; applies to `#page-meta` and `@demo-script`.
- **One global only**: `window.SUITE = { copyText, flash, meta }` (plus `SUITE.demo` if the proposed helper is accepted).
- **One clipboard path** (`copyText`) and **one status path** (`flash`) for every transient message; `#status` has `role="status"`; no `prompt()` or `alert()` anywhere. ST-7, ST-8.
- **Events are delegated from `document`** — one `change`, one `input`, one `click`, dispatched on `closest("[data-card],[data-section],[data-filter],[data-held]")`.
- **Capabilities are probed, never assumed** — `CAN_LS` by write-probe, `CAN_FS` by `typeof window.showSaveFilePicker`; `[data-needs="fs"]` elements are stripped when unavailable.

## B10. Card authoring

- Fixed body order: `.chiprow`, `h3`, optional `blockquote`, prose and evidence, engine `.respond` last. CO-8.
- The agent writes the `&lt;article&gt;`, its chiprow, its `h3` and its prose — and nothing else.
- The card edge colour is a `border-left` driven by `data-tag`, never a class kept in sync. DS-11.
- Optional article attributes: `data-tag`, `data-verdicts` (pipe-separated), `data-recommended` (exact option text), `data-answer` (`verdict` | `options` | `none`).
- Verdict sets live on the article, not in `#page-meta` — a card-keyed map in JSON drifts from the cards it names.
- On an options card, `checked`, `.recommended` and `data-recommended` **must agree**; a mismatch is a build error (S5).
- A quote is `&lt;blockquote&gt;&lt;p&gt;…&lt;/p&gt;&lt;cite&gt;You · session YYYY-MM-DD&lt;/cite&gt;&lt;/blockquote&gt;` — shell CSS only, engine generates nothing; a multi-turn exchange is consecutive blockquotes each with its own `&lt;cite&gt;`.
