## On the JSON question — answered up front

Inline works. External import mostly does not, on `file://`.

- `fetch('./config.json')` from a page opened by double-click: **blocked** in Chrome and Firefox. Local file origin is opaque; the scheme fails CORS. Same for `import cfg from './config.json' with {type:'json'}` — ES modules need CORS too.
- `<script src="./config.js"></script>` assigning `window.PROMPT_CONFIG = {…}`: **works**. Classic scripts are exempt. This is the way to get a separate editable file with zero server.
- `<script type="application/json" id="config">` in the head: works, single file, edit in place.
- Runtime import via `<input type="file">` or drag-drop: works, and gives you loadable prompt packs.

Recommendation: inline JSON block as the built-in default, plus a file-picker "load pack" and "export pack" pair. Single file stays single. No server, no build.

## 3 · Claude launcher tab

**Lands, with one caveat and one accuracy problem.**

The caveat is quoting, and it's not cosmetic. A built prompt has newlines, quotes, and backticks in it. `claude -p "..."` breaks on all three. The launcher has to emit a heredoc:

## Task

PROMPT

Quoted delimiter, so nothing inside expands. Get that wrong and every copy-paste is a debugging session.

## On shipping with dev-workspace

Worth its own pass, but one thing to flag now because it cuts against the current design: a shipped tool wants its config separated from its code, so `dev-workspace rebuild` can replace the HTML without eating your loadout. That's the opposite of the single-file design.
