=== My Solution ===

The standard solution is the issue's own prose: state the rule as a list-shape mandate in `notation.md`, give a worked split in `condition-writing.md`, and add a saddler check that names "and", "once", "unless", or a comma series as the splitting triggers. The rule reads *a condition block is a markdown list; a compound clause joined by these words is multiple conditions and splits into one item each.*

Your instinct is right that the trigger words are the weak part. They are surface features standing in for the real property, and they fail in both directions. They over-fire: "the report has arrived and is unchanged" is a legitimate compound where the shared subject makes one fact read naturally across a conjunction, and "no verdict is recorded unless a repair was requested" may be one state with a carve-out rather than two states. They under-fire completely on the case that actually motivated the issue — a convoluted prose blob with no conjunction in it at all ("the situation has settled into a reviewable state") is a single sentence, passes every word test, and is exactly the defect you want caught.

Worse, a word list invites the checking agent to grep instead of judge. The saddler's other condition checks all name a *property* and give a test that exercises it — de-hold asks whether the condition stops holding, exhaustive asks whether the agent could claim completion while work remains. The shape check written with trigger words is the only one in the group that would ask the agent to pattern-match rather than reason, and it would sit oddly beside its siblings.

=== Basic Solution ===

State only the shape, drop the splitting rule entirely.

`notation.md` gains one bullet: a condition block is a markdown list; each condition is its own list item. `condition-writing.md` gains nothing — it already demonstrates list form in every example. The saddler check becomes purely structural: *a condition block is a markdown list — prose paragraphs under a machinery heading are a finding.*

This catches the blob, which is the defect the issue actually observed, and catches nothing else. It is a genuine mechanical pass/fail, so it belongs cleanly in the Lint sweep and needs no judgement at all. It also produces zero false positives on the existing corpus, because everything already uses bullets.

The cost is that it does not catch the fat bullet — one list item carrying three facts. That defect survives, and it is the more common one in practice.

=== Advanced Solution ===

Anchor the rule to a testable property instead of to words: **one condition, one observable fact, one verdict.**

The rule becomes — *each list item states a single fact about the world that the agent can answer true or false by looking. An item requiring two separate observations to answer is two conditions.* The test the saddler runs: read the item, ask how many distinct things you must look at to decide it. One look, one item. Two looks, split.

This subsumes the trigger words without naming them, because a genuine compound requires two observations and a shared-subject conjunction requires one. "A report has arrived and no verdict is recorded" — two looks, split. "The report has arrived and is unchanged" — arguably still two looks, split, and correctly so. "The situation has settled into a reviewable state" — one look but the look is not observable, which the existing *checkable* test already condemns.

`condition-writing.md` carries the authoring form: split until each item answers to a single look, and where the alternatives are genuinely different world-states, close the list and open another with the separator. The issue's worked example survives intact as the demonstration — three facts and an alternative, becoming two lists — but it illustrates the counting test rather than the word list.

=== Alternative Solution ===

Put the weight in the guidance and keep the check thin.

`condition-writing.md` carries a full worked transformation: a bad condition block shown as written, then shown split, with the reasoning narrated. `notation.md` states the shape rule in one line. The saddler check names the property in a sentence and points at the reference for the detail — *conditions state one observable fact per list item; see the drafthorse skill's condition-writing reference for the split.*

This respects that the saddler is an auditor, not the spec, and keeps the checker's line count down. The problem is that the saddler audits documents standalone and may not have the drafthorse skill loaded — a check that outsources its own criterion is a check that sometimes cannot run. The saddler's checks are all self-contained today, deliberately.

=== Unusual Solution ===

Make the machinery heading do the work it already implies.

The headings read "when **these** are true". Treat that plural as normative rather than incidental: the rule becomes *the heading promises a set, so the block delivers a set — a block with one item, or with items that are not each independently readable as "this is true", contradicts its own heading.* The check is then a coherence test between the heading and its block, which is a shape the saddler already uses elsewhere (the separator's wording echoing the headings is called out in `notation.md` as intentional).

It is elegant and it needs no new vocabulary. But it accidentally forbids the single-condition block, which is legitimate — some steps genuinely have one entry fact — and it would need a carve-out that costs more than it saves.

=== My Recommendations ===

Take the Advanced solution. The counting test — one item, one observation, one true/false verdict — is the property the trigger words were groping at, and it is stated in the same register as every neighbouring check in `Condition Checks`. It catches both the blob and the fat bullet, it gives the auditing agent something to reason with rather than grep for, and it degrades gracefully: where a compound is genuinely one observation, the test lets it stand, which the word list would not.

Fold one piece of Basic into it. The plain structural fact — a condition block is a markdown list — should still be stated flatly in `notation.md`, because it is the mechanical half and it is what makes the Lint sweep line honest. So `notation.md` gets the shape (list, one condition per item), and the observation-counting test lives in the saddler check and the authoring reference where judgement belongs. That also settles the Lint line: sweep for list shape mechanically, leave the per-item split to the judged pass.

Drop the trigger words from all three files. If a hint is wanted for the authoring reference, let the worked example carry it — showing "a report has arrived and no verdict is recorded" split into two items teaches the conjunction case by demonstration, without promoting a word list to a rule. And I would keep "unless" out entirely: it usually signals an OR group rather than a split, so naming it as a splitting trigger would actively mislead.
