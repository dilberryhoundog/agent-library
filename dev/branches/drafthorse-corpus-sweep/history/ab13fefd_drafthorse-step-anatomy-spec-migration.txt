[ASSISTANT 💬]
Agree. The split kills the no-op, because a function check is conditional by construction — no advisory language needed, absence simply means the check never fires.

Concrete placement I'd argue for:

**`The run resolves`** — one check, Document-Wide. Every path ends somewhere stated, by an exit step or by the agent's own handling. Judged on the scenario walk, which is where resolution is actually observed rather than inferred. Nothing about presence.

**`Error step`** — a function check. Owns the three obligations: claims the remainder, handles destructives, accounts for half-applied state. Fires only when the step exists.

**Two half-applied findings stay in Step-Shape.** A step silently resuming over its own partial work, and a start condition carrying an exclusion clause. Both are defects with or without an error step, so they do not belong under a conditional check. The exclusion clause especially — it is a permanent hold, and it already caught a real instance in classroom.

## One hole to close before you commit

Function checks key on the **declaration**. A document can carry an error step without declaring `**Error step**` — undeclared reads as ordinary work. Key the check on the declaration and an undeclared error step escapes the remainder check entirely.

Error is the exception among the seven: its obligations follow from what the step *does*, not from what it declares. Suggest triggering that one on behaviour — a step claiming the remainder — and the other six on declaration.

The same gap is harmless elsewhere. An undeclared loop that loops fine needs no audit; the check verifies a declaration is truthful, not that every shape is labelled.

## What the section then covers

- **Error step** — remainder claimed, destructives handled, half-applied accounted.
- **Routing step** — every branch it opens is claimed by some step's start condition.
- **Looping step** — the condition re-holds, and something ends the loop.
- **Dormant step** — its state is reachable; a dormant step no run can enter is dead.
- **Handover step** — control returns to it; its finished condition reads the state left behind.
- **Support step** — the difficulty it claims is one another step actually produces.
- **Success step** — starts on the exhaustive all-done state.

Each tests one thing: does the declared shape resolve?
