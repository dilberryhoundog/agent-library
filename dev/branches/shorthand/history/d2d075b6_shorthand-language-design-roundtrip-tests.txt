**Blocks I couldn't confidently expand**

- **"git info/ignore. keeps upstream repo clean. keep drafts longterm. source of truth."** (line 14) — this holds a contradiction. If `*.draft.md` goes in `.git/info/exclude`, the draft file has no history, no backup, and is invisible to any other clone — which is the opposite of "longterm source of truth." Either drafts are ephemeral working files (exclude them) or they're the source of truth (commit them, keep `main.md` as the build artifact). Pick one; the spec currently claims both.
- **The default scope is implicit.** Four scopes are named (Preserve, Remove, Question, Explain) but every draft in this file uses none of them — the base "expand me into prose" function is unnamed. State that an unscoped `+DRAFT:` means "draft content, expand it," or the scope list reads as exhaustive when it isn't.

- **Question lifecycle** — Question is "decision clarification" and Explain is "decision reasoning," which is a thin distinction. More importantly: who answers a Question, and where does the answer land — a new Explain comment, an edit to the draft, chat? Unstated.

**Rule the spec breaks itself**

"A shorthand block is 2-6 words long" — several blocks in this file run 7-9 words ("Expansions directly under each draft for inline" is seven; the rule sentence itself is eight). Either loosen the rule (2-8 reads truer to your actual usage) or it will generate spurious violations the moment you build a checker.

**Structural gaps**

- The core pipeline is never stated as a pipeline. That `draft.md` expands into `main.md`, and which direction is authoritative, has to be reverse-engineered from the CLI block ("copy file -> convert to md -> run draft strip"). One draft near the top naming the flow would anchor everything else.

- Parity checking (line 105) has no defined invariant. "In sync" needs the round-trip stated: every block accounted for in the prose, no prose without a backing block. It falls out of the line-40 contract, but the link isn't drawn.

**Small stuff**: typos "Exisiting" (line 46) and "seperator" (line 49); "Drafts deformat" (line 52) is cryptic even by shorthand standards — I think it means "a comment inside a comment terminates the draft early," which is worth the extra words.
