# Shorthand

Write Markdown in Shorthand "blocks": deliberate statements of 2-6 words, each ending with a period. Markdown structure is untouched — bold, bullets, and tables are kept. The user tunes the agent's output, and full expansion follows when they are happy.

## Philosophy

Shorthand keeps agents on track. Thoughts, decisions, and instructions are condensed, and the agent's changes are edited before committal. It is an easy brain dump into Markdown — the agent understands.

## Style

Write in a telegraphic register. Articles are optional, verbs stay strong, and hedges and qualifiers have no place. The result still reads cleanly.

## Writing

One claim per block — a complete thought, then a period. Use full words only. Any valid markdown is allowed, provided the block rules still apply.

```md
## Rollout

Feature-flag new parser. Two-week canary. **Rollback**: error rate doubles.
```

## Tuning

The user reviews the blocks: shuffling, rewording, adding, deleting. User and agent revisions stay in shorthand. The loop runs until satisfied.

## Expanding

Expansion comes after tuning: shorthand expands on approval. The prose is stylistically free with the foundation preserved — round-trip compatible prose. Every block is accounted for, and no new claims appear. Build the document's structure as normal.

## Compressing

Existing prose is converted to shorthand — a faithful, mechanistic rendering. Every claim becomes a block, load-bearing modifiers are kept, nothing dropped, nothing added.

## Inside full documents

New shorthand rides in HTML comments, and the comments hold shorthand only. Place them above the passage or inline. They are invisible when rendered and removed after expansion.

## Agent edits

Agents write shorthand before full prose: propose the compressed shorthand in comments, and the user tunes the blocks.
